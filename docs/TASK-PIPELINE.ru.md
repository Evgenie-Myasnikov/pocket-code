# От карточки к проверенному результату

[Документация](INDEX.ru.md) · [English](TASK-PIPELINE.md)

**Ещё не выпущено.** Нужны обновлённые хост ПК и интерфейс. Задача использует
существующую доску репозитория и аккаунт AI на подключённом компьютере.

## Подготовка задачи

1. Откройте сохранённую заметку с описанием и критериями готовности.
2. В блоке **Выполнение** выберите провайдера и **Подготовить чат задачи**.
3. Приложение создаст отдельную ветку и рабочую копию Git из текущего коммита `HEAD`.
   В чате появится подготовленный запрос. Проверьте его и отправьте, чтобы запустить AI.
4. Строка задачи под шапкой чата открывает её результат, проверки и диф.
   В заметке сохраняется список запусков: новая попытка не стирает предыдущую.

Незакоммиченные файлы остаются в исходном проекте и **не копируются** в задачу.
Если они нужны, сначала создайте коммит. Зависимости вроде `node_modules` тоже не
устанавливаются автоматически. Репозиторий без первого коммита или недоступная папка
дадут понятную ошибку; запуск в исходной папке вместо изоляции не выполняется.

Несколько задач могут работать одновременно в разных копиях с учётом лимита провайдера.
Это разделение изменений файлов, а не отдельные аккаунты AI или системная песочница.
Выбранный режим доступа провайдера продолжает действовать.

## Проверки и одобрение

Этапы: **Работа → Проверки → Ревью → Одобрено**. Ошибка, остановка и структурированный
запрос ответа видны отдельно. Обычный вопрос в тексте AI не всегда распознаётся как
событие, если провайдер не сообщает о нём явно.

В **Результате задачи → Команды проверки** можно взять скрипты проекта или добавить
программу и JSON-массив аргументов. Например, программа `node`, аргументы
`["--test", "tests/example.test.mjs"]`. Команды выполняются напрямую в копии задачи,
без подстановок оболочки. `.cmd`/`.bat` не принимаются; найденные npm-скрипты запускаются
через Node и npm CLI. Сохранённый список запускается автоматически после завершения AI.
Пустой список отключает автопроверки.

Вывод ограничен по размеру, обрезанный вывод помечается. Есть тайм-аут и завершение
дочерних процессов при остановке хоста. Неуспешная или прерванная проверка блокирует
одобрение. Изменение файлов требует повторной проверки. После одобрения кнопка
**Продолжить задачу** снимает прежнее одобрение.

**Изменения задачи** показывают все изменения относительно исходного коммита:
закоммиченные, незакоммиченные и новые файлы. Доступны слитный и раздельный диф,
сворачивание файлов, фильтры расширений и размер кода. Файлы результата остаются
в обычном разделе результатов этого чата, обсуждение — в переписке.

Перед **Одобрить проверенный результат** посмотрите диф, чат и критерии готовности.
Успешная команда доказывает только результат этой команды. Одобрение привязано к
проверенному состоянию файлов: новые правки делают его неактуальным. Оно не выполняет
merge, push или публикацию и не подтверждает автоматически все требования задачи.

## Сохранение и восстановление

Связи с чатами, попытки, вывод проверок и одобрения хранятся приватно на ПК. В JSON
доски в Git они не записываются. Этап выполнения задачи не заменяет статус карточки
в дорожной карте автоматически. **Исходная карточка** открывает ту заметку, из которой
начали работу; удаление или недоступность доски показываются как ошибка.

Ветки и копии не удаляются автоматически. После перезапуска хоста прерванная задача
не стартует сама: посмотрите её чат и продолжите явно. Повтор запроса с тем же ID
не создаёт новую копию. Конфликт редакций требует обновить данные. Если исходный проект
удалён из разрешённых папок хоста, API перестаёт открывать его задачи.

## Уведомления

Включите уведомления чатов в настройках и разрешите их в системе. Windows и Android
получают события из сохраняемого журнала хоста: до 1 000 событий за семь дней. Курсор
и ID событий позволяют догрузить пропущенное после переподключения и убрать повторы.
Нажатие открывает нужный чат/запуск и провайдера из любого раздела.

Для задач Pocket Code доступны завершение, ошибка и структурированный вопрос.
Для запусков вне приложения доступны только завершение/остановка, которые обнаруживает
монитор истории провайдера. Нужны связь с ПК и системные разрешения; ограничения батареи
и принудительная остановка Android могут препятствовать доставке. Это не облачный push.
Назначения на доске и уведомления Miro остаются отдельными механизмами.
