# Решение проблем

[Документация](INDEX.ru.md) · [English](TROUBLESHOOTING.md)

## Первые проверки

Запишите версию телефона из **Настройки → О приложении**, версию сервера, выбранного провайдера и действие, после которого возникла ошибка. Проверьте, включён ли ПК и работает ли Pocket Code в трее. Попробуйте открыть историю изменений проекта: это поможет отличить проблему связи от ошибки AI или Jira.

Не начинайте со сброса всего. **Отключить и забыть** удаляет подключение и кэш чатов, но не исправляет авторизацию провайдера или занятый порт.

## Подключение и запуск

| Симптом | Что проверить |
| --- | --- |
| ПК недоступен через мобильный интернет | Включите интернет-режим в настройках подключения Windows либо используйте доступный адрес частной сети. Домашний LAN-адрес сам по себе не работает из другой сети. |
| После перезапуска туннеля перестало работать | Отсканируйте новый QR. Временный адрес мог измениться. |
| Закрыл браузер, сервер остался | Это ожидаемо: соединением управляет приложение Windows. Команда в трее → Выход завершает приложение и принадлежащий ему сервер. |
| Порт 4318 занят | Текущий лаунчер использует уже запущенный распознанный Pocket Code. Чужой процесс он не завершает. Уточните владельца порта или выберите другой порт. |
| Всё ещё нужно вводить папку/Enter | Запускается старый файл лаунчера. Обновите исходники/лаунчер; одна установка APK не заменяет этот скрипт. |
| Сразу нет Git-проектов | Поиск постепенный и пропускает системные каталоги, кэши и ссылки. Проверьте разрешённые корни и выбор проекта в новом чате или истории изменений. |
| После автообновления сервера нет нужных папок | Автоперезапуск сохраняет старые корни доступа. Один раз перезапустите обновлённый обычный лаунчер либо укажите ProjectPath явно. |

Для ограниченного доступа запустите PowerShell-команду `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -ProjectPath D:\Projects`. Для интернет-туннеля добавьте `-Internet`. Корневая папка ограничивает доступ, а не просто фильтрует список.

## Чаты и AI

| Симптом | Что сделать |
| --- | --- |
| OAuth истёк | Повторите вход в соответствующем нативном AI-инструменте на ПК. QR — отдельное подключение. |
| Codex rejected request / -32600 | Прочитайте сопутствующий текст. Один код не определяет причину. Проверьте версии и владельца Desktop-чата; сохраните черновик и повторите после устранения указанной причины. |
| Старый чат читается, но отправка недоступна | Освободите его для записи в Desktop либо проверьте разрешённые папки проекта. |
| Не все чаты видны | Проверьте провайдера и локальный аккаунт, дождитесь обновления и убедитесь, что история локальная и поддерживаемая. Облачные и удалённые Copilot-сессии не импортируются. |
| Второй чат не запускается | Общая или вложенная папка проекта блокируется. Выберите другой проект либо заранее созданную worktree. На провайдера допускаются три выполняющиеся задачи. |
| Нажал Stop без связи с ПК | Телефон не может гарантировать остановку без доступа к серверу. Восстановите связь и проверьте задачу перед конфликтующей работой. |
| Лимит недоступен | Аккаунт/runtime может не передавать его либо запрос завершился ошибкой. Это не означает нулевой расход. |
| Ошибка Windows 1058 у инструмента | Сохраните полный текст и проверьте названный runtime/службу Windows. Один номер не является основанием включать произвольные службы или менять защиту системы. |

Для Copilot запустите вход из **Настройки → Аккаунты AI → Аккаунт AI**, завершите браузерный шаг на ПК и проверьте подключение. Через пять минут вход может завершиться по тайм-ауту; перед новым входом завершите активные Copilot-задачи.

## Review, файлы и результаты

Если изменений меньше ожидаемого, проверьте режим **Все / Подготовленные / Ветка**, базовую ветку, папку чата, свёрнутые файлы и скрытые расширения. Сравнение ветки не включает незакоммиченные правки. Игнорируемые файлы отсутствуют, а двоичные/большие могут не иметь текстового дифа. После восстановления связи обновите данные: кэш не подтверждает текущее состояние диска.

Если код выходит за экран, включите **Диф по ширине экрана**. Если стал слишком мелким, отключите подгонку и задайте фиксированный размер кода. Он не совпадает с масштабом интерфейса и размером текста чата.

Если результаты неполные, дождитесь индексации истории и проверьте фильтры категории/источника. Повторное открытие запускает сканирование заново; после ошибки остаются частичные результаты и повтор. Удалённый файл нельзя восстановить только по старому пути. Внешнюю картинку нужно загрузить явно. Просмотр текущего файла не всегда соответствует его исторической версии.

Правила и история изменений открываются для чтения. Единственный подходящий документ показывается сразу, несколько — списком. Показанный документ не добавляется автоматически как новая инструкция AI.

## Совместимость с Jira и PR

В основном интерфейсе используются доски репозиториев и Miro. Настройки подключения Jira и прежние серверные API сохранены, но вкладка задач Jira, выбор роли и очередь больше не показаны. Проверки ниже относятся к интеграциям или старым клиентам.

| Симптом | Что проверить |
| --- | --- |
| В Claude Jira работает, прямой MCP заблокирован | Разным клиентам нужна отдельная авторизация. Может потребоваться одобрение прямого клиента администратором сайта. Используйте разрешённое подключение. |
| Смена AI не меняет аккаунт Jira | Это ожидаемо: у сервера одно выбранное общее подключение Jira. |
| Описание не загрузилось | Повторите открытие задачи и проверьте доступ коннектора; ошибка получения не означает пустое описание. |
| Нельзя сменить статус без оценки | Заполните обязательные поля перехода. Неподдерживаемые проверки/поля обрабатываются в самой Jira. |
| PR не создаётся | Проверьте GitHub CLI, корень репозитория, ветку задачи, чистую рабочую папку и коммиты. Приложение не коммитит посторонние файлы за вас. |
| В колокольчике нет старых уведомлений | Он начинает с исходного состояния и отслеживает последующие изменения; это не полный inbox Jira. |

После прерванной записи проверьте задачу/PR и сохранённую ссылку перед повтором. Удалённая операция могла завершиться, даже если ответ потерялся. Восстановление не отменяет изменения в сервисе.

## Обновления и уведомления Android

Если старый APK выдаёт **Invalid update source**, один раз установите актуальный APK поверх существующего. Нужны тот же пакет и подпись; удаление приложения перед установкой может стереть локальные настройки. Android требует разрешение и подтверждение установки, поэтому полностью незаметное обновление APK не поддерживается.

Обновление Windows и сервера ждёт завершения работы и передачи APK, проверяет пакет и перезапускается. При неудачном запуске возможен откат. Смотрите статус обновления, не прерывайте передачу управления принудительно. Начиная с 0.21.1 проверкой обновлений и подготовкой APK управляет ПК; он не ждёт обновления телефона. На телефоне доступна кнопка «Проверить обновления на ПК». На ПК нужен доступ к GitHub/npm.

Для уведомлений чата проверьте разрешения Android, канал **Chat results and questions**, не вышли ли вы явно из последнего чата, связь с ПК и фоновые ограничения Android. Уведомления сервиса задач работают отдельно от уведомлений чатов. Браузерный интерфейс не предоставляет нативный фоновый сервис Android.

## Как сообщить об ошибке

Укажите версии приложения/сервера, провайдера, шаги, ожидаемое и фактическое поведение, воспроизведение на вымышленном проекте. Для вёрстки добавьте размеры экрана, масштаб и размер текста. Скрывайте частные сведения на скриншотах; не публикуйте QR/ключ, токены, реальные переписки, рабочие задачи и приватные пути. [Создать issue](https://github.com/Evgenie-Myasnikov/pocket-code/issues).
